# 真实星空、太阳与月亮设计规格

## 目标

在足迹页的 3D 地球场景中加入：

- 约 50 颗全天最亮恒星。
- 当前真实 UTC 时刻的太阳方向。
- 当前真实 UTC 时刻的月亮方向与月相。
- 与地球视角一致的透视、遮挡和时间旋转。

对象位置必须来自真实天文坐标，不使用固定屏幕背景。用户旋转地球时，天体应作为三维场景对象随相机视角正确变化；被地球遮住时必须自然消失。

## 非目标

- 不显示恒星、太阳或月亮名称。
- 不显示星座连线。
- 不提供历史或未来日期选择器。
- 不按真实距离绘制天体；距离会为了画面压缩。
- 不实现以某个城市为观察点的地平坐标天空。

## 坐标基准

观察基准为地球整体，而不是某个城市。

1. 恒星目录保存 J2000 赤经、赤纬、视星等和颜色指数。
2. 每次时间快照先把恒星坐标转换到日期对应的赤道坐标。
3. 太阳和月亮使用地心真实视位置。
4. 使用现有 `latLngToVector3()` 把赤经和赤纬转换为场景中的天球方向。
5. 使用格林尼治视恒星时旋转天球组，让它相对地球纹理产生正确的周日运动。
6. 太阳的地球固定方向单独传给昼夜着色器，并用现有 `solarDirection()` 做符号和轴向回归测试。

场景中的地球北极保持 `+Y`。所有天体和地标共用同一中心、同一坐标轴向和同一摄像机。

## 时间更新

- 使用当前 UTC 时间。
- 天文快照最多每 5 秒重新计算一次。
- 恒星天球在渲染帧中按地球自转角连续旋转，避免每分钟跳动。
- 页面不可见或地球画布离屏时停止更新。

## 数据与计算

### 依赖

新增 `astronomy-engine`，使用其太阳、月亮、日期赤道坐标和恒星时能力。该依赖为 MIT 许可。

### 恒星目录

新增静态文件 `XHBlogs/data/brightStars.ts`：

```typescript
export interface BrightStar {
  id: string;
  name: string;
  rightAscensionHours: number;
  declinationDegrees: number;
  magnitude: number;
  colorIndex?: number;
}
```

- 收录约 50 颗最亮恒星。
- 数据按视星等从亮到暗排序。
- 名称只用于开发识别和无障碍说明，不渲染标签。
- 恒星坐标为 J2000。

### 天文快照

新增 `XHBlogs/lib/celestial.ts`：

```typescript
export interface CelestialSnapshot {
  capturedAt: Date;
  celestialRotationRadians: number;
  sunDirectionEarthFixed: [number, number, number];
  sunCelestialDirection: [number, number, number];
  moonCelestialDirection: [number, number, number];
  moonLightCelestialDirection: [number, number, number];
  moonIlluminatedFraction: number;
  starsCelestial: Array<{
    id: string;
    direction: [number, number, number];
    magnitude: number;
    colorIndex?: number;
  }>;
}
```

函数职责：

- 校验无效日期。
- 计算日期对应的赤道坐标。
- 将赤经和赤纬转换为单位方向。
- 将 J2000 恒星方向转换到日期对应坐标。
- 计算地心太阳、月亮和月球受光方向。
- 生成与地球纹理坐标一致的地球固定太阳方向。
- 生成只应用一次的天球旋转角；实际逐帧旋转在 Three.js 组上完成。

## 3D 渲染

新增 `CelestialSphere` 组件，并与 `Earth`、地点标记放在同一 `<Canvas>` 场景中。

### 恒星

- 使用一个或多个 `THREE.Points` 渲染。
- 星点大小为 `1–3px`，按视星等调整。
- 最亮恒星可带轻微暖色或冷色。
- `depthTest` 开启，地球可以遮挡后方恒星。
- 星点不写深度缓冲，避免影响其他标记。
- 恒星天球半径采用画面用值，不作为真实距离。

### 太阳

- 使用暖色发光球核加径向光晕。
- 方向约每 5 秒更新，渲染帧间可平滑插值。
- 太阳方向同时驱动地球昼夜着色器，避免昼夜线错位。
- 使用深度测试，太阳转到地球背后时被遮挡。

### 月亮

- 使用球体几何和自定义光照着色器。
- 亮面方向来自太阳到月亮的方向。
- 月相由球面真实受光决定，不使用预先绘制的月相贴图。
- 显示轻微的暗面颜色，避免背光面完全消失。
- 使用深度测试，月球转到地球背后时被遮挡。

### 视角转换

天体不跟随 HTML 容器或屏幕坐标定位。它们只使用 Three.js 世界坐标：

- 赤道坐标天体先放入 `CelestialSphere` 组。
- `CelestialSphere` 在地球北极轴上按恒星时连续旋转。
- 相机旋转时由投影矩阵完成透视转换。
- 天体被地球遮挡时由深度缓冲处理。
- 更新天球时间时只旋转天球基准，不改变地球大小、卡片尺寸或摄像机距离。

## 错误处理

- 日期无效时抛出明确错误，由单元测试覆盖。
- 天文计算失败时隐藏天体和太阳，但地球页仍正常显示。
- 无 WebGL 时继续使用现有静态地点列表回退。
- 页面不可见时暂停时间更新和动画帧计算。

## 性能

- 恒星使用点云，不为每颗恒星创建 React 组件。
- 月亮和太阳各自最多使用少量网格。
- 不加载额外远程纹理。
- 不增加页面容器高度。
- 避免每秒触发 React 重渲染；天文快照低频更新，连续旋转在 `useFrame` 内完成。

## 测试

### 纯函数测试

- 恒星星表至少有 45 项且按视星等排序。
- 所有恒星坐标范围合法，方向向量长度为 1。
- 已知日期的太阳赤纬方向和现有昼夜逻辑一致到合理误差。
- 已知新月和满月附近的月球照亮比例分别接近 0 和 1。
- 月亮受光方向为有限单位向量。
- 无效日期被拒绝。

### 集成检查

- 足迹场景包含 `CelestialSphere`。
- 天体几何启用深度测试。
- 页面不可见时天球更新停止。
- `/footprints` 静态构建成功。

## 验收标准

1. 打开足迹页后能看到散布在地球周围的最亮恒星。
2. 太阳和月亮位置随当前真实时间变化。
3. 月亮亮面朝向当前太阳方向，显示真实月相。
4. 旋转视角时，天体按三维透视移动，不固定在屏幕。
5. 天体转到地球后方时被地球遮住。
6. 不出现加载跳动、布局变化或明显帧率下降。
