# 旅行足迹地球仪设计规格

日期：2026-11-28

## 目标

在现有博客中新增“足迹”页面，用真实 3D 地球展示已经去过的旅行地点。每个地点记录到访日期、备注和对应照片；点击地点时显示从杭州到目的地的弧线。

第一版使用静态旅行数据，不提供可视化录入后台。数据结构必须为后续接入后台编辑保留清晰边界，届时不需要重写地球组件。

## 不在本期范围

- 可视化新增、编辑或删除地点
- 用户账号和旅行数据 API
- 地理编码搜索，以及从城市名自动获取经纬度
- 为不同旅行分别生成独立公开页面
- 上传照片；第一版只复用已有图片 URL
- 多地球主题、扁平地图或 2D 地图模式

## 页面入口

- 主导航在“照片墙”之后新增“足迹”，路径为 `/footprints/`
- 页面沿用当前博客的导航、背景、中文衬线字体和玻璃质感界面
- 页面标题为“足迹”，辅助文字用于表达旅行记录，不引入新的站点身份设定

## 核心体验

### 地球

- 使用真实 3D 球体呈现地球
- 同时使用白天地表贴图和夜间城市灯光贴图
- 根据当前真实 UTC 时间计算太阳直射方向
- 在光照方向基础上混合昼夜纹理，形成随当前时间变化的晨昏线
- 晨昏带使用柔和过渡，不使用生硬的黑白分界
- 默认缓慢自动旋转；用户拖拽后暂停自动旋转，空闲一段时间后恢复
- 支持鼠标滚轮或双指缩放
- 缩放到合理范围，不允许进入地表或移出视口
- 桌面端和手机端都使用同一个 Three.js 场景，只调整渲染质量和控制方式

### 地点标记

- 杭州作为起点展示，但不作为一个普通的“已旅行目的地”
- 所有目的地以可见标记投射在球面上
- 位于地球背面的地点标记不穿透球体显示
- 标记大小保持稳定，不因相机距离变化而过度缩小
- 鼠标悬停或触摸时显示地点名称
- 点击目的地后进入选中状态

### 杭州出发弧线

- 平时不显示所有旅行弧线，避免画面拥挤
- 只有点击目的地后，才显示杭州到该目的地的大圆弧线
- 弧线从杭州坐标开始，以目的地坐标结束
- 弧线沿球面大圆插值，并通过高度曲线抬离地表，形成清晰的空间航线
- 弧线显示时带一次短促的展开动画
- 再次点击其他地点时，旧弧线淡出，新弧线出现
- 点击空白处或关闭详情面板时取消选中并隐藏弧线

### 地点详情面板

- 桌面端从右侧展开，手机端从底部展开
- 面板显示：
  - 城市名
  - 国家或地区
  - 每次到访的开始日期和可选结束日期
  - 每次到访的旅行备注
  - 与该地点关联的照片
- 同一地点有多次到访时，共享一个地图标记，在面板内按日期倒序显示
- 照片采用缩略图网格；点击后复用现有照片大图预览交互
- 没有照片时只显示日期和备注，不留空白占位框
- 照片未填写备注时使用地点名称作为图片替代文本
- 面板必须可通过关闭按钮或 Escape 关闭

## 静态数据模型

数据文件：`data/travel.ts`

```ts
export interface TravelVisit {
  date: string;
  endDate?: string;
  note?: string;
  photos: string[];
}

export interface TravelPlace {
  id: string;
  name: string;
  country: string;
  coordinates: [longitude: number, latitude: number];
  visits: TravelVisit[];
}
```

固定起点：

```ts
export const hangzhouHome = {
  name: "杭州",
  coordinates: [120.1551, 30.2741] as const,
};
```

约束：

- `id` 唯一，只允许小写字母、数字和连字符
- `name` 和 `country` 去除首尾空白后不能为空
- 经度范围为 `-180` 到 `180`
- 纬度范围为 `-90` 到 `90`
- `visits` 至少包含一项
- `date` 和 `endDate` 使用 `YYYY-MM-DD`
- 填写 `endDate` 时不得早于 `date`
- 照片路径必须是站内绝对路径或合法的 HTTP(S) URL
- 同一地点的访问按日期倒序展示

首版目的地数据至少包含东京，并使用已有“旅游剪影”中的涩谷照片。杭州只作为固定起点，不写入目的地列表。后续补充其他地点时复用同一结构。

## 技术方案

### 渲染栈

- `three`
- `@react-three/fiber`
- `@react-three/drei`，仅在确实需要时引入控制器或加载能力
- Next.js 客户端组件负责浏览器端渲染

不引入完整地球可视化框架，以免限制晨昏着色和弧线动画的定制能力。

### 组件边界

`app/footprints/page.tsx`

- 静态页面与元数据
- 挂载客户端足迹页面

`app/footprints/FootprintsClient.tsx`

- 页面布局
- 当前选中地点状态
- 地球与详情面板之间的数据传递

`components/TravelGlobe.tsx`

- Three.js Canvas 和相机
- 地球、标记、杭州弧线
- 当前时间对应的太阳方向
- 拖拽和缩放交互

`components/TravelDetailPanel.tsx`

- 地点、日期、备注和照片
- 关闭交互
- 使用现有大图预览能力

`lib/travel.ts`

- 数据校验
- 经纬度转三维向量
- 大圆弧线采样
- 太阳位置和方向计算
- 不包含 React 或 Three.js 渲染代码

### 昼夜着色

- 地球材质使用自定义 ShaderMaterial
- 白天纹理、夜间纹理和光照方向作为 uniform 传入
- 片元着色器根据表面法线与太阳方向点积混合纹理
- 点积接近晨昏线时增加暖色过渡带
- 太阳方向以当前 UTC 时间计算，并按当前日期更新
- 页面每 60 秒更新一次太阳方向，避免每帧进行不必要的日期计算

自动旋转通过旋转相机或控制器实现，不直接改变地球模型相对太阳的朝向。这样经度与昼夜位置保持一致。

### 弧线

- 使用球面归一化向量插值生成大圆采样点
- 在插值点基础上按球面距离增加径向高度
- 使用 `THREE.Line` 或等价的线性几何绘制
- 选中地点变化时更新几何数据
- 卸载组件时释放几何、材质和纹理资源

### 资源

- 纹理放在 `public/images/globe/`
- 不使用远程 CDN 作为运行时依赖
- 优先使用公版地球昼夜纹理，并控制文件体积
- 地球纹理必须能在桌面和手机网络下快速加载

## 性能与回退

- 桌面端设备像素比上限为 `2`
- 手机端设备像素比上限为 `1.5`
- 手机端降低球体细分和纹理清晰度
- 页面离开视口或标签页隐藏时暂停自动旋转
- WebGL 上下文创建失败时显示静态地球封面、说明文字和地点列表
- 贴图加载期间显示轻量加载状态，不显示空白黑块
- Three.js 组件必须只在客户端加载，避免静态导出和服务端渲染错误

## 可访问性

- 地球画布提供中文可访问名称
- 地点详情使用可聚焦、可关闭的对话框语义
- Escape 可关闭详情
- 所有按钮提供可见焦点状态
- 标记点击不仅依赖颜色，还显示地点文字和图形变化
- 关闭动画时，面板与弧线仍能立即完成切换

## 测试与验收

### 单元测试

- 合法地点数据通过校验
- 重复 ID、空名称、越界坐标和非法日期被拒绝
- 填写结束日期早于开始日期时被拒绝
- 杭州到东京弧线首尾坐标与输入一致
- 不同经纬度会产生不同的太阳光照方向
- 经纬度转换为单位球向量

### 页面测试

- 导航包含“足迹”并指向 `/footprints/`
- 页面包含地球 Canvas 的可访问容器
- 详情面板包含城市、日期、备注和照片入口
- WebGL 回退内容存在

### 浏览器验收

- `/footprints/` 在桌面端正常加载 3D 地球
- 地球显示当前时间对应的昼夜和晨昏线
- 拖拽、缩放和自动旋转正常
- 点击东京后出现杭州到东京的弧线
- 详情面板显示东京对应日期、备注和照片
- 点击照片打开大图预览
- 点击关闭按钮、空白处或按 Escape 后弧线消失
- 手机端使用底部详情面板，触摸缩放和拖拽正常
- 禁用 WebGL 后仍能看到地点列表和说明

### 工程验证

- `pnpm test`
- `pnpm exec tsc --noEmit`
- `pnpm build`
- Cloudflare Pages 部署成功
